# 검증 자료 (verify/)

PDF 원본(도로교통공단 문제은행 2026.3.9 시행)에서 **앱 데이터와 별개 경로로** 추출한
ground truth. 앱이 문제를 정확히 반영했는지 교차검증한다.

## 파일
- `answer-key.csv` — 1,000문항의 번호 / 정답 / 유형 / 보기개수. 기준 데이터.
- `verify.mjs` — `src/data/bank.json` 과 `public/q/` 를 answer-key.csv 와 대조.
- `spotcheck.md` — 사람이 눈으로 대조할 랜덤 15문항 전문.

## 실행
```bash
node verify/verify.mjs      # 프로젝트 루트에서
```
종료코드 0 = 통과, 1 = 실패.

## 검사 항목
1. 문항 수 1,000 / 번호 누락·중복
2. **정답 1,000건 전수 일치** (가장 중요)
3. text/img 유형, 보기 개수 일치
4. 복수정답 282문항 수 일치
5. 이미지 카드 293장 존재, 깨진 파일
6. 지문 정답 노출, 해설·지문·보기 누락, 정답 번호 범위

## 확정된 수치 (v2 기준)
| 항목 | 값 |
|---|---|
| 전체 | 1,000 |
| 문장형 `text` | **707** |
| 이미지형 `img` | **293** |
| 이미지형 중 5지선다 | **185** (nc=5) |
| 이미지형 중 4지선다 | **108** (nc=4) |
| 복수정답(2개 선택) | 282 |

## 신뢰 근거
- 정답 1,000건을 pdftotext / PyMuPDF 두 경로로 추출해 대조 → 불일치 0건
- 원문자 변종(①➀⓵❶ⓛ / ⑤➄⓹❺) 전부 포함해 보기 개수 재검사 → 5지선다 185로 확정
- 검증 스크립트에 고의로 오류를 주입해 실제 탐지되는지 확인

## 알려진 예외 (오류 아님)
- **해설 없는 3문항**: #418, #643, #964 — 원본 PDF에 해설이 없다.
- **보기 5개**: 이미지형 293문항 중 185개가 ⑤까지 있다. UI는 `nc`만큼 버튼을 그려야 한다.
- **한 글자 보기**: #262, #264, #405, #549, #651 등은 보기가 "5", "10" 같은 숫자 한 자리다. 정상이다.
- 이미지형은 보기 텍스트가 카드 안에 있어 `c` 필드가 없다.
